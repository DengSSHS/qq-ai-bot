# QQ 交互：引用 / 表情回应 / 拍一拍

2026-10-26 加。这四件事让群聊理解力和拟人感都上一个台阶。

## 入站：引用展开（原来就有，但缺一半）

`get_msg` 解析早就在（`inbound.js` 的 `expandQuote`）：带 `reply` 段的消息会被展开成
`[引用]昵称: 原文` 再交给她。**缺的是出站**——她从来不会「引用某条消息再回」，
所以看起来像"听不懂上下文"。

## 入站：拍一拍（新增）

QQ 的「拍一拍」是 `notice` 事件（`notice_type=notify, sub_type=poke`），原管线只认 `message`，
**这一拍在桥接层就被丢了**——她根本不知道有人拍她。

现在 `bridge.handlePokeNotice()` 会把它合成一条入站消息：

```
[拍一拍] 神神很衰 拍了拍你（这是 QQ 的「拍一拍」动作，不是发消息）
```

- 只处理「拍的是她」，拍别人不管
- 同一个人 3 秒内连拍只算一次
- 她看到之后自然回应一句就行（"怎么了？"）

## 出站：三个新工具

`message_id` 现在会带进上下文（`<user_message … message_id="…">`）——
不带的话下面两个工具全成摆设（实测踩过）。

| 工具 | 作用 | 限制 |
|---|---|---|
| `qq_reply(message_id, text)` | 引用某条消息再回，比干巴巴发一句更像人 | 无 |
| `qq_emoji_like(message_id, emoji_id="76")` | 给消息贴表情回应，**零 token** | 同一条 1.5 秒冷却 |
| `qq_poke(user_id)` | 拍一拍对方 | 只允许主人/白名单，冷却 10 分钟 |

`limits.json` 可调：

```json
"poke_cooldown_min": 10,
"poke_allow": "",            // 逗号分隔的熟人 QQ 号，主人自动在名单内
```

拍一拍的实现细节：管理员名单在 `bridge.deps.policy.adminUsers`（不是 `config`），
另外并上 `poke_allow` 和 service 里的 `OWNER_QQ` —— 之前取错位置导致白名单为空、
她报「没权限」，这个坑记在这儿。

## 实测

```
引用回复   她说「收到」→ 真的走 reply 段发出去 ✓
拍一拍入站 [poke] 转成入站消息：[拍一拍] 神神很衰 拍了拍你… ✓
拍一拍出站 她说「拍到了。」→ 主人收到拍一拍 ✓
表情回应   合成 id 会返回 msg not found（注入测试正常现象）；
           真实消息 id 才能点，需在真聊天里验证
```

## 已知边界

- `qq_emoji_like` 依赖消息真的存在于 NapCat（注入的测试消息 id 是造的，会 `msg not found`）。
- 拍一拍在群里也走同一套逻辑，但白名单限制让它只能拍主人/熟人——这是刻意的。
- 引用展开只有一层（引用的引用会展开成被引用那条的原文）。
