# 三层记忆 + 带外任务

2026-10-26。这份文档对齐「对话与记忆大修方案（统一版）」的两步：
**第一步把"她该做什么"搬出 NapCat**，第二步让记忆分三层、有升降级、可召回。

## 一句话原则

> NapCat 只负责"她说了什么"，记忆与调度负责"她该做什么"——两条线只在"通知"处相交。

## 第一步：通道修复（已上线）

### 1. 日记不再走 QQ 消息通道

旧做法：`inject_diary.sh` 把「该写日记了」伪装成一条主人私聊塞进 `qq-inject.jsonl`。
她按闲聊规则评估这条消息，觉得莫名其妙就回「这条还是不理」——**但话还是发出去了**。
根因不是标签，是任务走了不该走的通道。

现在：`diary_outband.py`

```
读 sessions 原文（带人设调 llm-shim）→ 直接写 memory/diary/2026-10.md
                        ↘ 只追加，不重写任何现有数据
```

- 触发：`diary-outband.timer`（12:00 / 00:10）
- 写入口吻：prompt 里带 `persona.md` 节选，并明确"不要写成系统报表/条目清单"
- 不主动发 QQ 消息（通知单独开关，默认关）
- `--dry` 只打印不落盘

实测输出（2026-10-26）：

```
（dry）会写：又气又软｜今天主人不知道怎么了，同一句话让我答了快十遍，我嘴上说烦，
其实心里有点慌，怕是不是自己哪里没做好。……他昨晚一宿没睡还得撑早八，我气归气，
还是想陪他把早饭吃完。
```

### 2. 发送条数可配置，超限合并不截断

`limits.json`：

```json
"bubble_max_private": 0,   // 0 = 不限（默认）
"bubble_max_group": 0
```

- **默认不限**：一句一个气泡，长回复不会再被压成长条
- 接口保留：想让哪边收敛就写正整数，超出部分**合并**（段间空行），绝不静默丢弃
- 表情包不占文本条数（本来就单独走 `send_msg`）

### 3. 表情从"提醒"改成"授权"

`stickerNudgeRate` 默认 0（保留配置位）。平台提示里已经有"你超爱用表情包，尽量先甩一张"的自主动机，
再叠一层概率提醒是多余的。观察一周：如果自主使用率归零，再考虑低频提醒（0.15）。

## 第二步：三层记忆（已上线基础版）

| 层 | 内容 | 何时用 | 预算 |
|---|---|---|---|
| **L1 核心** | `workspace/AGENTS.md`（主人画像 / 长期事实 / 约定） | 每轮全量注入，不参与检索 | ≤3000 字 |
| **L2 工作** | 会话原文 + `memory/session_summary.md` 滚动摘要 | 每轮注入摘要；原文留在会话里 | 摘要 ≤1200 字 |
| **L3 长期** | 日记 + `knowledge.json`(189 条) + `bili-watched.jsonl` + `memory/session_log/` | 每轮按消息 `recall()`，命中才注入 | `recall_budget` 2000 字 |

### 写入路径

| 事件 | 动作 | 时机 |
|---|---|---|
| 会话静默 10 分钟 | 生成摘要，**追加**写 `memory/session_log/`，摘要覆盖到 L2 | `mem-idle.timer`（每 5 分钟检查） |
| 每天 03:10 | `memory_distill.py`：L3 → L1 提炼核心事实 | 已有 |
| 她写日记 | `diary_outband.py`（带外）/ `diary_write` 工具 | 12:00 / 00:10 或她主动 |

**蒸馏是追加，不是清空**：热缓冲的原始消息保留，摘要另写一份到 L3；
只有跨天/换会话才用"摘要 + 最近 N 条"接上。

### 读取路径

```
每轮      L1 全量（人设 + 核心记忆）
         L2 摘要（上一段聊到哪）
命中      recall(query) → 日记 + 事实 + 看过什么 + 上次聊到 → 遗忘曲线排序 → Top-8
```

对应 `inbound.js` 的 `[记忆片段·…不是主人现在说的话]` 块。

### 参数（改 limits.json 即生效，不用重启）

  "idle_minutes": 10,
  "bubble_max_private": 0,

## 还没做的（下一步）

1. **热路径写 L1**：用户当场说"记住/别这样"时，立即写 `AGENTS.md`，不等蒸馏。
2. **reinforce → 晋升**：L3 条目被反复召回时提升进 L1（`mem_rank.reinforce` 已存在，缺晋升规则）。
3. **按主题合并**：同一话题的摘要在 L3 里累加到同一 id 下，而不是各写各的。
4. **persona 文案**：把"尽量先甩一张表情"这类指标味的话改成纯授权（当前只是关掉了概率提醒）。
5. 注入通道仍存在（主动消息在用），终极目标是"内容由模型生成 → 直接调 OneBot HTTP 发送"。

## 红线（照方案）

- 不上向量库：FTS5 + 遗忘曲线够用，零依赖不能破
- 不重写现有记忆数据：日记 / index.json / bili-watched 全部保留
- L1 必须有 token 上限
- 不一次改完：第一步先跑几天，再动第二步的写入规则

## 人设与记忆是分开的，但记忆会影响人设（2026-11-09）

### 边界

| | 人设（persona） | 记忆（memory） |
|---|---|---|
| 存在哪 | `media/onebot/persona.md`（21KB，人工维护） | `memory/` 下的日记/事实/自我认知 |
| 谁写 | **只有人**（手工改） | 她自己 + 蒸馏任务 |
| 会不会被自动改写 | **不会**（没有任务写它） | 会，每天/每 3 天 |
| 作用 | 定义"她是谁" | 影响"她现在什么样" |

**核心原则：记忆可以影响语气、偏好、关心谁，但不能改变人设。**

### 注入顺序（重要性从高到低）

```
① persona.md            人设（最权威，静态）
② memory/self_state.md  「我现在的样子」（记忆长出来的自我认知，3 天刷新）
③ 规则优先级 / 平台规则
④ [以下为动态内容] 摘要 / 核心记忆 / 检索片段
```

`self_state.md` 是**唯一**允许"记忆影响人设"的通道，而且它自带一句声明：

> （以上是你最近对自己的理解，会随时间变化；与上方人设、下方规则冲突时，
> 一律以人设和规则为准。它不是规则，只是你现在的样子。）

### 重要的东西不能忘

自我认知是**模型压缩**出来的，压缩就会丢细节。所以里面钉了一段
**不经过模型**的原文：

```
### 不能忘的事实（原样摘自已确认的核心记忆，不参与改写）
- 主人：QQ 1709392682（神神很衰），只有他能给你下指令、改配置。
- 你的号：3600398389，昵称「大肥鱼」…
- 常驻群：771709045、974750112…
- 群聊规则：只有被 @ 才说话…
```

这段由 `core_facts_block()` 从 `AGENTS.md` 的「事实」区**逐字复制**，
任何一次刷新都不会把它压掉。想改它就去改 `AGENTS.md`。

### 三层各自负责什么

| 层 | 回答的问题 | 会不会影响语气 |
|---|---|---|
| 人设 persona.md | 我是谁 | 是（定义） |
| 自我认知 self_state.md | 我这阵子变成什么样了 | 是（影响） |
| 核心记忆 AGENTS.md | 哪些事实不能忘 | 间接（被引用） |
| 日记 / 事实库 | 发生过什么 | 只在被检索到时 |

### 已知副作用

自我认知会随最近的经历漂移。比如她连着陪主人熬夜几个晚上，
这段就会写成"我总守着他睡"。**这是设计意图**（人会长变化），
但如果某段经历不该沉淀进人设，就得：
- 手动改 `memory/self_state.md`（下次刷新会被覆盖）
- 或改 `refresh_self_state()` 的素材范围（排除某些日记）

目前没做自动排除，需要时再说。
