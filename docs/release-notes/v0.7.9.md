# v0.7.9 · 表情：每轮递一句话提醒，让她自己想起来用

> 我想要的就是他可以自己选择使用，但是我想要这个频率调高一点

v0.7.5 我修了 `sticker_pick` 的 scene 失配（此前她一张都发不出来），
但很快发现还是不够：**她只在你明确要求时才发表情**。

## 为什么人设写“每三四条带一条”没用

模型在组织一条文字回复时，**不会自发停下来问“要不要多调一次工具”**。
人设能影响她说什么，影响不了她要不要多走一轮工具调用。所以那句频率要求等于没写。

## 改法：每轮把念头递到她眼前（不替她做决定）

在消息尾部按概率附一句极短的提醒（`stickerNudgeRate: 0.6`）：

```
（顺手想一下：这条要不要配张表情？三成左右该配一张。
  拿不准就配——qq_random_sticker() 一次调用就能发出去。）
```

- 由**她自己决定**用不用 —— 符合“她自己选择”的要求
- 60% 的轮次出现 —— 常常提醒，但不会变成每次都有的背景噪音
- 放在消息**尾部**，不影响提示前缀缓存

## 中间踩的坑：配置写了却完全没效果

第一版加完后实测 5 轮，**一次提醒都没有**。原因不是逻辑错，而是插件的配置是
**显式白名单**转发：

```js
const gateConfig = {          // 这个对象是白名单
    casualEngageRate: config.casualEngageRate,
    ...
};
```

新键不写进这个对象，pipeline 侧读到的永远是 `undefined`，
于是 `?? 0` 把它变成一个安静的 0 —— 配置明明写在 yml 里，行为却毫无变化。

这类 bug 特别值得记下来：**没有报错、没有日志、配置看起来生效了，实际什么都没发生。**

## 实测

```
注入 4 条普通消息 → 4 轮输入里都带上了提醒（stickerNudgeRate=0.6）
同时观察：16 轮里她自发用了 1 次表情（此前为 0）
```

一次样本还不足以下结论，但方向对了：**没人要求，她自己发了**。

## 没验的

- 频率是否真的落在“三成左右”——需要跑半天到一天统计才准
- 群聊里的效果（注入通道进不了群）

## 顺带

`apply_local_patches.py` 已登记这处补丁（schema + 白名单 + 提醒注入三处），
重装不会丢；`cordis.patch.yml.tpl` 也补了 `stickerNudgeRate`。
