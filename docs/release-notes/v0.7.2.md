# v0.7.2 · 假在线：WS 连着不等于她还在线

一个 20 多分钟没人知道的失联，暴露了看护的盲区。

## 发生了什么

2026-10-24 22:51，她突然不回消息了。`qqguard`（每 2 分钟）判断是**在线**——因为
OneBot 的反向 WebSocket 一直是 `ESTAB`。

真实情况：腾讯把登录态作废了，NapCat 日志里写着

```
快速登录错误： 你的用户身份已失效，为保证账号安全，请你重新登录。
```

QQ 客户端已经退出登录，只有 daemon 的 WebSocket 还挂着。看她的人在 23:14 才
自己发现不对——中间 23 分钟没有任何告警。

## 为什么原来的看护发现不了

| 信号 | 断线（能发现） | 假在线（发现不了） |
|---|---|---|
| OneBot WS 8643 | 断 | **连着** |
| 容器进程 | 活 | 活 |
| 群里发消息 | 收不到 | **也收不到** |

原来 `onebot_connected()` 只看 WS 是否 `ESTAB`。这个信号在绝大多数故障里够用，
唯独对"QQ 侧退登但桥还连着"完全瞎。

## 改了什么

`qqguard.py` 加了一条平行判定：WS 连着 **且** 命中下列任一 → 判为「连着但登录态失效」，
立刻发邮件（邮件里带二维码附件和授权链接）。

```
登录态已失效 / 用户身份已失效 / 请扫描下面的二维码 / 需要验证码 / Login Error,ErrType
```

或者容器里 10 分钟内新生成的 `qrcode.png`（说明此刻正等人扫）。

**这里故意不重启容器**：实测重启只会换一张新二维码，还可能把人工正在扫的那张刷掉。
「登录态失效」不是重启能解决的，缺的是让主人知道。

识别逻辑抽成纯函数 `classify_log()`，新增 `tests/test_qqguard_logout.py` 8 个用例盯着——
NapCat 改日志文案，测试会立刻红，而不是等到下次真出事才发现检测失效。

## 顺带补的一次事故

部署时发现服务器上的 `qqguard.py` 比仓库里的**新**（线上多出 `_mail_alert`、
`_pull_qr`、`_qr_url`，会拉二维码当附件发邮件）。差点被我的版本覆盖掉。
现在仓库与线上已对齐，两边功能都在，离线告警和假在线告警共用 `_mail_alert`。

顺带记一笔：那封 23:19 的邮件**其实发出去了**（收件人 QQ 邮箱），
只是当时 QQ 侧的掉线是"重启容器"造成的假警报，真正的退登反而没触发。

## 自验

```
python -m unittest discover -s tests   -> 114 tests OK (skipped=3)，新增 8 个
preflight.sh                           -> 71 passed / 0 failed
```

部署后在服务器上验了三件事：

| 场景 | 结果 |
|---|---|
| 当前健康 | `在线（已检查）`——不误报 |
| 伪造"15 分钟前起登录失效" | `连着但登录态失效 15 分钟（登录态已失效）`，dry-run 显示本应发告警 |
| 复原状态 | 回到 `在线（已检查）`，`logout_since` 清零 |

**没验的部分**：没有真的制造一次退登来端到端验证邮件送达（那需要让账号再掉一次）。
邮件通道本身今晚 23:19 已经证明可用。
