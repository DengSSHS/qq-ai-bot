# v0.7.10 · qqguard 两个修正：不再自动重启、不再误报假在线

今晚 01:55 又掉线了，查下来**问题在 qqguard 自己**。

## 修正一：默认不再自动重启容器

```
01:55:01  检测到 OneBot 断线
01:55:01  检测到新的 KickedOffLine → 重启容器尝试快速登录
01:55:24  重启后仍需扫码，二维码已生成，等待人工
```

它看到腾讯踢线就重启容器，指望“保存的登录令牌”能自动恢复。但这台机器
**每次重启都必须重新扫码**（整晚 4 次，0 次成功）。于是重启不但没救回来，
还：

- 把原本可能还有效的令牌换成了“待扫码”状态
- 把人工正在扫的那张码刷掉（接下来每 2 分钟 NapCat 换一张新码，人根本扫不了）

改成默认不重启，只告警：

```python
AUTO_RESTART = os.environ.get("QQG_AUTO_RESTART", "0").lower() not in ("0", "", "false", "no")

if not AUTO_RESTART:
    log("检测到 KickedOffLine；AUTO_RESTART=false，不重启容器，只发告警")
    return "离线，已抑制自动重启（等人工扫码）"
```

用环境变量而不是删代码：换到“重启真能快速登录”的环境，`QQG_AUTO_RESTART=1` 即可恢复旧行为。

## 修正二：假在线误报

扫码上线后，`get_status` 明明返回 `online:true / good:true`，消息收发也正常，
但 qqguard 报：

```
连着但登录态失效 1 分钟（二维码已生成，等人扫）
```

原因：`qr_fresh()` 只看「二维码文件是不是 10 分钟内生成的」，而登录成功后
那张码文件还留在盘上 → 被判成“还在等人扫”。

改法：判失效之前**先直接问 NapCat 在不在线**（`online_confirmed()`）：

```python
live = online_confirmed()
mark = logout_since(window) if live is not True else None
waiting_scan = qr_fresh() if live is not True else False
```

- 明确在线 → 不判失效，清状态
- 明确离线 → 按原逻辑判
- 问不到 → 才退回日志/二维码判据（fail-safe）

顺带的好处：它检测到“登录态已恢复”后会真的发一条恢复通知
（`message_id 576710354`），这条比以前那个假的“已告知”可靠。
