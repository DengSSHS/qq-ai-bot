# v0.7.22 · 发现冲突要主动提醒，不是等他去看日志

> 不过，如果发现有这种问题，然后应该要跑一遍检测，然后给他发一个提醒的

v0.7.21 做了"不覆盖"，但只打印在终端里——**他未必会去看日志**。
所以补上主动提醒：检测到「你改过的文件」就发一条 QQ。

## 提醒长这样

```
【更新时发现 1 个文件被你改过（未覆盖）】

这些文件你（或使用者）改过，更新时保留了你的版本，没有覆盖：
  - proactive.py

新版本已经放在同目录的「文件名.new」里，你可以：
  1. 什么都不做 —— 继续用自己的版本
  2. 用新版 —— 把 .new 覆盖过去
  3. 先看差异 —— diff -u 文件名 文件名.new

提醒：改插件（node_modules）请用 apply_local_patches.py，那个不会被更新冲掉。
```

## 两个关键细节

**1. 同一次冲突只提醒一次**

签名存 `memory/deploy-conflicts.json`（文件名 + 新版哈希前缀）。不然每次更新都刷一遍，
提醒会变成噪音。

**2. 提醒发失败就不记「已提醒」**

第一版写完我发现这个坑：只要调用了 notify 就写状态，**不管有没有发成功**。
结果一次通道抽风，这条提醒就永久静默了。

改成只有 `returncode == 0` 才落状态，失败会打印「下次更新会再试」。

## 自验

```
第一次同步 → 通知 1 条
第二次同步 → 同一冲突，静默（仍 1 条）
通知失败   → 不写状态文件，下次重试
线上实发   → QQ 已发（message_id 1167981623）
```

## 顺带

`update.sh` 里已经调用 `sync_scripts.py`，所以这个提醒在
「手动 update」「凌晨自动更新」两条路上都会生效。

如果哪天真被提醒了，也不用紧张：文件没被动过，`.new` 就在旁边等着你决定。
