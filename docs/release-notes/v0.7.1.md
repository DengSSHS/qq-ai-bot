# v0.7.1 · 让别人一眼看得懂，让 AI 一条命令装完

这次没有新功能。改的全是"别人第一眼看到什么"和"AI 第一次动手做什么"。

## 问题在哪

之前仓库里**一张图都没有**，README 开头是五行参数，然后直接掉进 18 个小节的文字墙。
想装的人得自己从 `README.md`、`START-HERE.md`、`DEPLOY.md`、`MANUAL.md` 四份文档里
拼出一条安装路径——这四份各写了一遍"怎么装"，顺序还不完全一样。

AI 那边更糟：它不知道先读哪份，也不知道**什么算装完**。

## 改了什么

### 1. 配图：仓库第一眼能看到东西

`docs/img/banner.png`（头图）+ `docs/img/architecture.png`（链路图）。
都由 `scripts/gen_images.py` 用 Pillow 画，改文案重跑即可，不需要设计工具。

图里只放能自验的数字：607 MB / 1~2 秒 / 7 个 MCP / 0 依赖。

> 踩坑：中文一开始用 Consolas 渲染，"插件""模型"全变成方框——Consolas 没有中文字形。
> 现在中文一律微软雅黑，只有纯英文标识符用 Consolas。

### 2. 一条命令：`deploy.sh`

```
查 deploy.env（5 项必填 + QQ 号格式 + 人设模式 + 权限）
   ↓
install.sh（幂等）
   ↓
verify.sh（实况验收）
```

以前要记 `cp` → `install.sh` → `verify.sh` 三步，现在一条。
失败信息统一成 `[FAIL] 原因 + 怎么办`，退出码跟 verify.sh 一致。

顺手修了一个真实的坑：`deploy.env` 在 Windows 上用记事本改会写成 CRLF，
bash 读出来每个值尾巴多一个 `\r`，QQ 号校验直接失败，而报错看不出是换行符问题。
现在 `deploy.sh` 会检测并 `sed` 掉。

### 3. `AGENTS.md`：给 AI 的机器入口

新增 `AGENTS.md`（AI 工具链的默认读取约定），一页写清：三条命令、必须问的 5 个问题、
装完东西在哪、**5 条红线**（不许跳过 verify.sh、不许提交密钥、不许留 `{{占位符}}` 等）、
5 个常见坑对应的原因，以及交付时只能说一句结论。

它只是索引，权威内容仍在 `START-HERE.md`；两者冲突以 START-HERE 为准。

> 注意别混淆：**仓库根目录的 `AGENTS.md` 是部署说明**；
> **服务器上的 `/opt/dsh/workspace/AGENTS.md` 是运行时记忆文件**（每天 03:10 蒸馏写入、
> 每轮对话注入）。同名但不是一回事，README 里已标注。

### 4. README 重排

- 顶部：头图 + 5 个徽章（release / ci / license / python / 0 依赖）+ 一段话说清它是什么
- 「部署：一条命令」提前到第二屏，之前埋在第 80 行
- 「快速开始」和「部署」内容重复 → 合并成「安装细节」，只留扫码、Windows、CRLF 这些真需要的
- 架构图给图，同时保留可折叠的文字版（便于搜索、复制、喂给 AI）
- 加了可折叠目录

## 自验

```
bash preflight.sh   -> 71 passed, 0 failed, 1 warnings（pyyaml 未装，跳过 YAML 解析）
python -m pytest    -> 106 passed
```

`verify.sh` 没有在干净机器上重跑（这次只动文档和脚本，没碰部署逻辑），
所以这次发布的诚实结论是：**静态检查和单元测试通过，干净机部署未复验**。
