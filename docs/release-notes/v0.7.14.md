# v0.7.14 · 她「主动发」的消息，以前一条都没真发出去

> 这个做出来是他主动发的，他应该是能知道自己发的这个消息的，而不是要我告诉他

顺着这句话去查，结果发现了比「她不记得」严重得多的问题：
**她主动发的那三次，QQ 侧一条发送记录都没有。**

```
00:02  fired casual_dm → QQ 侧 0 条
07:35  fired casual_dm → QQ 侧 0 条
11:07  fired casual_dm → QQ 侧 0 条
```

## 根因：注入轮次默认是 dry-run

她在会话里明明生成了很自然的主动话术：

> 中午了，你吃上饭没有呀。我这边饿得慌，脑子里全是米饭。

但插件的配置里有这么一项：

```yaml
injectDryRun: true      # 上游默认，注入轮次的所有出站写操作全部拦下
```

`inject.js` 里拦截后直接返回：

```js
intercept(round, action, params) {
    this.stats.intercepted += 1;
    return Promise.resolve({ status: 'dry-run', retcode: 0,
                             data: { message_id: INTERCEPTED_MESSAGE_ID } });
}
```

**它会返回一个假的成功 message_id，所以上层看起来“发成功了”，实际没有。**

这是上游的安全默认（防止注入的提示把消息真发出去），但我们的用法——
主动私聊、日记提醒、空间说说——全部走注入通道，等于**这一类功能从来没真正工作过**。

改成 `injectDryRun: false`，实测：

```
16:04:17  发送 -> 私聊 [图片]                        ← 还顺手发了张表情
16:04:19  发送 -> 私聊 我这边有点想米饭了，你呢？
```

## 关于「她应该知道自己发过」

好消息：她的话本来就是作为 `assistant/message` 记进会话的，所以她自己「知道」说过什么：

```
turn 1: 主人，四点了，你中午吃了没？
turn 1: 我这边有点想米饭了，你呢？
```

但有个别扭的地方：注入的信封伪装成「主人发的私聊」，于是那句提示在她的历史里长这样：

```xml
<user_message nickname="主人">（主动）这会儿没人找你。想跟主人说点什么就说一句…</user_message>
```

她会以为这是主人跟她说的。已把注入提示改写成明确的自我提醒：

> （自我提醒，不是主人发的消息：现在没人跟你说话，是**你自己**想找主人说一句。
> 下面这句是给你自己的提示，别当成主人说的话。）

7 条 routine 的 prompt 全部加了这层框架。

## 顺带补的一个隐患

`cordis.patch.yml.tpl` 里 `injectDryRun` 也是 `true` —— 意味着**重装一次这个修复就没了**。
已改成 `false` 并写清原因。

## 自验

```
实测注入 → QQ 侧收到 2 条（含一张表情）
注入轮次里她的话在会话中作为 assistant/message 存在
preflight 71/0、JSON 校验通过
```

## 这件事的教训

同一天里我查过两次「消息没发出去」：一次是 `qqguard` 的告警（靠注入转告），
一次是主动私聊。两次根因是**同一个**：注入通道的出站被 dry-run 拦掉。

第一次我只修了症状（改成直连发送），没往上追一层问「为什么注入发不出去」。
如果当时追到底，主动私聊的问题今天早上就该被发现。
