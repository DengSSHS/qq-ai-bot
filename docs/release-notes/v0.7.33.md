# v0.7.33 · 每天限制从代码里抽出来

> 我指的是 B 站的可以 @ 的数量
> 我觉得那个一天限制可以 @ 的数量，这个是不行的，这样反而还有点累赘
> 不过这个还是可以保留的，之后做面板的时候可以自定义

## 问题有多具体

B 站评论区 @ 主人原来是 **每天 3 条、间隔 20 分钟**，而且**写死在 `bili_hub.py` 里**。

实测一晚：

```
2026-10-24 22:24  BV1vKsKe8Eh4
2026-10-24 23:31  BV126nt6GE4W   有人专门复盘了这场「鱼灾」
2026-10-25 00:10  BV1hyWF61EnQ   把「给她完整的一生」套在鲸鲸身上了
2026-10-25 01:00  BV1AyJy6SESw   AI消失前假新闻大会
2026-10-25 01:38  BV1X1nB6mEAW   有人让AI拿方块搭了个大肥鱼
```

**五个视频想分享，配额只有三条**——后两个只能自己看。这就是"累赘"的具体形态。

同类硬编码还有三处：全局发送 400/天、主动私聊 8/天、半夜叫醒 1/晚。
它们散在 `cordis.patch.yml`、`routines.json`、`bili_hub.py` 三个地方，
**没人知道该去哪改**——这比数字本身更麻烦。

## 改法：集中到一个文件

`/opt/dsh/limits.json`（模板 `stack/config/limits.json.tpl`）：

```json
{
  "qq_action_per_day": 2000,
  "qq_action_per_minute": 20,
  "qq_rate_per_minute": 8,
  "bili_share_per_day": 10,
  "bili_share_interval_min": 8,
  "bili_share_same_video_days": 7,
  "dm_per_day": 8,
  "dm_night_per_night": 1
}
```

**改完立即生效，不用重启。**

| 项 | 原来 | 现在 | 为什么 |
|---|---|---|---|
| B 站 @ 主人 / 天 | 3 | **10** | 一晚五个视频都不够用 |
| 两次 @ 间隔 | 20 分钟 | **8 分钟** | 同一轮刷完就能连着说 |
| 同视频重复 @ | 7 天 | 7 天（不变） | 防重复，这个该留 |
| 全局发送 / 天 | 400 | **2000** | 实测每天 30~45 条，400 撞不到但撞上就是"发不出消息" |

## 能看、能改（面板前身）

```bash
$ python3 switches.py limits
每天/每小时限制（改：python3 switches.py set-limit <名字> <值>）
------------------------------------------------------------------------------
全局发送次数/天                     2000       撞上会表现为「她完全发不出消息」
发送次数/分钟                      20         防刷屏
接收处理/分钟                      8          防消息洪峰
B站评论区 @ 主人/天                 10         超过就不 @ 了，只自己看
两次 @ 最小间隔（分钟）                8
同视频多少天内不重复 @                 7
主动私聊/天                       8          她主动找你说话的次数上限
半夜叫醒/晚                       1          失眠那条路线
------------------------------------------------------------------------------
文件：/opt/dsh/limits.json（改完立即生效，不用重启）

$ python3 switches.py set-limit bili_share_per_day 20
[OK] bili_share_per_day = 20（已生效）
```

没有 GUI，但已经满足"能看见、能改、改完即时生效"——之后做面板时，
直接调这两个命令就行，不用再动代码。

## 自验

```
python3 switches.py limits          → 8 项全部列出
set-limit bili_share_per_day 5      → [OK] 已生效
bili_hub.limits()                   → 读到新值（daily_max 跟随）
set-limit not_a_limit 5             → 拒绝，并列出可用项
preflight 72/0、测试 137 passed
```

`install.sh` 会创建 `limits.json`（不存在时），`update.sh` 只补缺失的键、
**不改你调过的值**。
