# v0.7.16 · 内部提示改走系统侧，不再伪装成「主人发消息」

> 其实我更倾向于那个系统提示词注入从另外一个方面下手，而不是从我聊天入口

对，这才是根上的问题。之前的做法是：把内部提示（主动私聊、日记提醒、空间说说）
写进 `qq-inject.jsonl`，它被喂进真实入站管线——于是**在会话里长得跟"主人发的私聊"一模一样**：

```xml
<user_message qq="1709392682" nickname="主人">（主动）这会儿没人找你…</user_message>
```

她分不清这是系统在跟她说，还是你在跟她说。

## 改法：身份改标成「系统·内部提醒」

在 `inject.js` 的 `consume()`（注入事件进管线的最后一道关）改写事件：

```
sender.nickname  →  「系统·内部提醒」
正文前缀          →  [内部提醒·非用户消息]
```

现在会话里长这样：

```xml
<user_message qq="1709392682" nickname="系统·内部提醒">
[内部提醒·非用户消息] （内部测试）这条应该是系统提醒…
```

她一眼能分清：**这是系统给我的提示，不是主人跟我说话。**

## 为什么不能彻底不走注入

查过 dsh 的能力：没有"主动开始一轮对话"的命令行或接口。**触发一整轮只能靠注入一条入站事件。**
所以能做到的最干净程度是：触发照旧，但**身份改成系统**，且不让它的回复自动变成聊天消息。

## 顺带：日记/空间不再给你发消息

那 4 条日记提醒 + 1 条空间说说，本来是内部任务（写日记、发空间），
但现在注入能真发消息了，她"写好了"之类的话会跑进私聊。

已给这 5 条 prompt 加尾巴：

> （这是内部任务：做完就结束，不要在 QQ 里给主人发任何消息。要说话只能通过写日记/发空间这些工具，不要回复这条提示。）

并标了 `silent: true`。

## 自验

```
node --check inject.js 通过
注入测试 → 会话里显示 nickname="系统·内部提醒" + [内部提醒·非用户消息]
apply_local_patches --check：6 处全「已打」
```

## 补丁从 5 处变成 6 处

新增的是 `inject.js 注入事件改标成系统提醒`。按之前定的规则（5 处是分水岭），
这一处是**必须拦在消息管线上**的（身份标记只能在入站改写），没有配置或 MCP 能替代，
所以值得加。已登记进 `apply_local_patches.py`，`patch_doctor` 会盯着它随上游漂移。
