# v0.7.17 · 修 idle：概率模型的地基原来是坏的

> idle_minutes() 依赖的 qq-actions.log 从未生成 → idle 恒为无穷大
> 这意味着你今天精心调的三层概率模型……建立在一个坏掉的输入上
> v0.7.12 想改掉的「越不理我越急」，因为 idle 恒为∞，行为上仍然是「越不理我越急」——只是参数变好看了

这条批评是对的，而且比表面更严重：**我两次在文档里写下这个问题，两次都没修。**

## 坏在哪

```python
def idle_minutes():
    return (time.time() - os.path.getmtime(ACTIONS)) / 60.0
    # ACTIONS = media/onebot/qq-actions.log
    # 文件不存在 → 异常 → return 1e9（无穷大）
```

`qq-actions.log` 只在**出站真的写操作**时生成。而 v0.7.14 之前注入轮次全是
dry-run（写操作被拦），文件从来没被创建过——于是：

- `idle` 恒为 1e9
- `hours = (idle - 60) / 60` 巨大 → `idle_bonus` 永远取满（0.30）
- 概率恒等于「半天没聊」那一档（晚上 47%）
- **「刚聊完 8%」这一列从来没被执行过**

所以 v0.7.12 写的「基础冲动 + 加成」、v0.7.13 的乘性设计，在行为上都没兑现：
实际跑的仍然是「你多久没理我，我就多想找你」——只是参数看起来更像活人了。

## 修法：取多个真实活动来源

```python
def last_activity_ts():
    """最后一次性活动（任一方说话）的时间戳。"""
    cands = [ACTIONS]                      # 她发出消息的时刻
    cands += glob('sessions/*/onebot-private-*/session.v4.jsonl.zstd')
    cands += glob('sessions/*/onebot-group-*/session.v4.jsonl.zstd')
    return max(os.path.getmtime(f) for f in cands if exists)
```

session 文件在**任何一方的回合**都会追加，所以它的 mtime 天然就是
「最后一次有人说话」——比她单向的发送记录更准。

## 修好后的实测

```
修之前：[casual_dm] 空闲 563 分钟｜概率 80%｜掷出 0.86 -> 不发
修之后：[casual_dm] 刚聊过（12 分钟前 < 60），不打扰
        [casual_dm_night] 空闲 12 分钟｜本轮概率 0%
```

概率分层终于真的存在了（晚上 21 点这一档）：

| 空闲时长 | 空闲加成 | 概率 |
|---|---|---|
| 刚聊完 | 0.00 | **8%** |
| 半小时 | 0.03 | 11% |
| 1 小时 | 0.05 | 14% |
| 2 小时 | 0.10 | 21% |
| 4 小时 | 0.20 | 34% |
| 8 小时以上 | 0.30 | 47% |

## 附带说明一件事

`qq-actions.log` 现在存在了（16:14）——因为 v0.7.14 关掉 dry-run 后，出站真的发生，
审计文件才被写出来。所以「文件存在」这件事本身就是 dry-run 那个 bug 的旁证。

## 教训

同一个缺陷我写了两遍说明（v0.7.12 和 v0.7.13 的「仍存在」小节），都没有修，
却继续在它上面叠新设计。**已知的坏输入不修，上面盖多少层都是假的。**

以后遇到「已知输入不可靠」，要么当轮就修掉，要么把依赖它的功能标成未启用——
不能一边记账一边往上加功能。
