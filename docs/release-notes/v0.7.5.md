# v0.7.5 · 表情包：从一天 0 条到真的会发

诉求很简单：「她太少发表情包了，想让她多发几个。」

先查数据，结果比“少”严重得多：

```
今天她的发送总数       76 条
其中带表情的            0 条
sticker_pick 调用       0 次
```

## 真因：scene 只认分类名，人设却让她传自然语言

`pick()` 的筛选是这样写的：

```python
if scene and scene not in s_scene:   # 精确子串匹配固定分类名
    continue
```

而人设告诉她：「把这次的场合写进 scene」。于是她传 `scene="群里有人在开玩笑"`，
一个分类都匹配不上 → 工具返回「这个条件下一张都没有」→ 她就放弃了。

现场实测：

```
sticker_pick(scene="群里有人在开玩笑")  → 一张都没有    ✗
sticker_pick()                        → 挑到 3 张       ✓
```

一个本该“让她更会用表情”的设计，实际效果是**让她一张都不发**。

## 改了三处

1. **`stickerlib.py`：scene 失配时退回全库**（保留 query、安全、防连撞过滤），
   并在返回里列出可用分类名，让她下次能说对。
2. **人设：默认改走一步到位的 `qq_random_sticker()`**。它自己的说明就是
   “聊天时随手甩一张表情就用它，不用先挑选”。两步流程（pick → send）实测她经常懒得走完。
3. **人设：频率写成可执行数字**——“大约每三四条回复带一条表情，同一条最多一张，
   同群一小时最多六次”，替掉原来那句毫无作用的“几乎每次聊天都会先甩一张”。

## 实测：修复后下一轮，她自己走完了全链路

```
[工具调用] mcp__sticker__sticker_pick(scene="无语尴尬")    ← 分类名对了
[工具结果] 挑到 3 张：菲比-呆菲 / 鲸鱼娘-603 / 鲸鱼娘-995
[工具调用] qq_send_sticker(query="cc13e04f89")
[工具结果] 已发送
[文本]     说不上低落，就是有点酸。…
```

## 没做的：确定性的 30%

「每条消息 30% 概率附加一个表情」需要改插件发消息的收口（本地补丁 5 处 → 6 处）。
凌晨改这段，改错的结果是她直接哑掉。所以先看这轮“人设 + 工具容错”能不能把频率拉起来；
若明天统计仍然偏低，再上确定性的那版，并且先在旁路验证过再替换。
