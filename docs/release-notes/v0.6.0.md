做的过程中还揪出一个我自己埋的坑，那个比开关更重要，先说那个。

## 先说坑：我引入了一次静默回归

为了让开源版不带私有地址，我把 `seer.py` 的默认 `BASE` 改成了
`https://api.deepseek.com`。当时验证过——能看图。

但验证方式有问题：我用的是临时脚本，**它跑在普通 shell 里，`seer.py` 用的是
自己的默认值（真地址）**。而 `dsh-onebot` 启动的 MCP 子进程，`VISION_BASE`
来自插件配置；**systemd 定时任务两个都没有**。

于是：

```
sticker-settle.service      03:00 收图结算   → 看图 401
memory-distill.service      03:10 记忆蒸馏   → 看图 401
```

隐蔽在于**今天完全看不出来**：settle 今天跑了两次都"成功"，因为当时没有新图
可判，压根没调模型。明天 03:00 第一次有图要判时才会炸，而报错只是
"判断异常: HTTP Error 401"，看不出是配置问题。

### 两层修复

1. `seer.py` 自己从 `qwen.env` 兜底读 `VISION_BASE`/`VISION_MODEL` ——
   任何 `python3 x.py` 的调用方式都不会踩，**包括以后新加的定时任务**
2. `sticker-settle` / `memory-distill` 补上 `EnvironmentFile=/opt/dsh/qwen.env`

验证：不带任何环境变量直接调 → `值得收=True safe=True`，正常。

## 开关面板 switches.py

```bash
python3 switch.py                # 列出现状
python3 switch.py off casual_dm  # 关掉私聊主动
python3 switch.py on  budget_breaker
```

11 个开关：

| 开关 | 现在 | 作用 |
|---|---|---|
| `casual_engage` | 开 | 群聊主动接话（20%，每小时最多 3 次） |
| `casual_dm` | 开 | 私聊主动找人（空闲越久概率越高） |
| `diary_reminders` | 开 | 早上/中午/傍晚/夜里提醒写日记 |
| `qzone_daily` | 开 | 每日说说提醒 |
| `sticker_settle` | 开 | 03:00 收图结算 |
| `memory_distill` | 开 | 03:10 记忆蒸馏 |
| `daily_report` | 开 | 23:55 日报邮件 |
| `qq_guard` | 开 | QQ 掉线看护 |
| `patch_doctor` | 开 | 每周补丁漂移检测 |
| `budget_breaker` | 关 | 预算熔断 |
| `content_screening` | 开 | 图片内容风险筛查 |

### 四种"插槽"

加新开关 = 往 `FEATURES` 加一条 dict：

| kind | 映射到 | 要重启吗 |
|---|---|---|
| `timer` | systemd 定时器 | 不用 |
| `config` | `cordis.patch.yml` 的键 | 要（自动重启） |
| `routine` | `routines.json` 的作息条目 | 不用（下次检查生效） |
| `budget` | `budget.json` | 不用 |
| `env` | unit 的 `Environment=` override | 下次触发生效 |

改文件前自动备份到 `memory/switch-backups/`，改完校验，校验失败自动回滚。

### 又踩了一次同一个坑

`routine` 和 `env` 两类最初**只改标记，代码没读**：

```
switch.py off casual_dm   →  casual_dm: {"off": true}
proactive.py              →  完全无视这个字段，照旧跑
```

所以补了两处读取逻辑。**这是本项目最顽固的一类 bug**：开关面板如果只改配置
不接行为，它本身就是个骗人的东西。
