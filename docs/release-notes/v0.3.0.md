这一版两件事：一个**刹车**（管钱），一道**闸门**（管别人的隐私）。

两个都是把「已经写好但没生效」的东西接到真正的路径上——和上一版修安装 bug 是同一个毛病：代码在，但没接对地方。

## 安装

```bash
git clone https://github.com/DengSSHS/qq-ai-bot.git
cd qq-ai-bot
cp deploy.env.example deploy.env   # 填 6 项
sudo bash install.sh
```

升级已有部署：拉代码后重跑 `install.sh`，或只同步 `stack/*.py`。

## 预算熔断：从「事后记账」到「事前刹车」

`usage_log` 只回答"花了多少"，而钱已经花掉了。现在有了闸门：

```
软线 80%   → 停非必要调用（看图判断、记忆蒸馏）
硬线 100%  → 主对话也停，返回 429 + 明确原因
```

分级的理由：主对话停下她就哑了，但"给表情打标签""整理记忆"这类批处理停下
完全无害，第二天额度恢复再跑。所以先砍后者。

拒绝时返回人话，她能如实转告：

> 今日 token 预算已用尽。**这不是故障，是预算熔断。**明天零点自动恢复；要立刻恢复就调高 `budget.json` 的 `daily_tokens`。

三个入口都接（网关 / 看图 / 蒸馏），计数复用 `usage.jsonl`，跨天自动归零。
闸门自身出异常**一律放行**——坏了不能把人锁在外面。

### ⚠️ 默认关闭

装完不会自动启用。这是个刹车，别人的日用量和模型价格都不一样，默认值猜错了
就是"机器人突然不说话了"。要用就：

```json
// /opt/dsh/budget.json
{ "enabled": true, "daily_tokens": 3000000, "soft_ratio": 0.8 }
```

不知道填多少，先跑几天看实测：

```bash
python3 usage_log.py --days 7
```

## 内容风险筛查：之前是「有代码、从未跑过」

`judge_safe()` 早在 `ingest` 里，但只有主动调用 `ingest` 才触发。实测线上全库
4130 条，**只有 1 条有 `safe` 字段，判定"不适合转发"的 0 条** —— 等于没跑。

同时结算阶段只问"值不值得收"，把隐私混在"不值得收"的理由里，不产出
`pick()` 能用的标记。

现在合并进结算的同一次模型调用，一次产出四个字段：

```
值得收? | 场景 | 适合转发? | 理由
```

落盘规则：

| 判断 | 处理 |
|---|---|
| 值得收 + 安全 | 进 `pending/`，等入库 |
| 值得收 + **不安全** | 挡在 `pending/` 之外，写 `extras[safe]=False` |
| 不值得收 | 删除（照旧） |

`pick()` 本来就会跳过 `safe is False` 的条目，所以风险图即使混进来也发不出去。

`safe` 缺失时判为 `None`（不确定），**绝不默认 True**——宁可多留一张让人看一眼。

实测：造了一张模拟隐私截图（姓名 / 手机号 / 快递单号 / 地址 / 工牌），
判定 `安全=False`，理由"含姓名电话住址隐私"。
