# v0.7.25 · 群聊里查不到日记和 B 站记录 + B 站窗口提前到晚 6 点

三个问题，一个是机制漏洞、一个是配置、一个是重复实现。

## 1. 别的群里她"想不起来"自己看过什么

用户反馈：在群里说不上来自己之前在 B 站刷到什么、也想不起今天的日记。

查了两个群的实际会话：

```
系统提示最长 12602 字 | 含记忆关键词 True      ← 长期记忆确实注入了
记忆类调用: diary_recent=1 diary_search=1 其它工具=35   ← 196 轮里只查过 1 次
```

**工具全在**（`diary_recent` / `diary_search` / `notes_read` 都在她的工具表里），
问题是**没有规则告诉她什么时候该查**，她也不会自发多走一轮工具调用。

先按常理补了人设规则，实测**没用**——问她"昨天 B 站刷到啥"，她凭印象答"没看"，一次都没查。
（和之前表情包同一个病：人设能影响"说什么"，影响不了"要不要多调一次工具"。）

所以改成机制：**关键词命中就提醒**。

```js
const MEM_TRIGGER = /(昨天|前天|上次|之前|记得|日记|笔记|你(今天|昨天|前天|之前)|看了什么|刷到|你说过)/;
if (MEM_TRIGGER.test(final)) final += MEM_HINT;
```

`MEM_HINT` 是：「先调 diary_recent 或 diary_search 查一下再答，别凭印象编；查不到就直说没记下来。」

用关键词而不是概率：这是有明确条件的事件（问到过去/自己经历），
随机提醒会在闲聊里乱插。

**实测（改完立刻验）**：

```
[工具调用] mcp__memory__diary_search {"query": "B站 视频", "n": 5}
[工具调用] mcp__memory__diary_recent {"n": 5}
[她的回答] 刚翻过日记了。昨天B站没看成，今天写的那些也跟刚才说的一样。
```

她说"刚翻过日记了"是真的翻了，不是编的。

## 2. B 站窗口：从晚 6 点开始

原来只有 `23:30–08:00`，而用户的要求是"差不多从晚 6 点就可以看"。

改 `18:00–08:00`。同时发现一个更实际的坑：

```
今天：自动开 3/3，手动开 2/2     ← 额度在凌晨 00:10 和 03:12 就用完了
能不能刷：不行（低谷期今天的自动额度用完了）
```

**窗口改早了，但额度还是会被凌晨吃光**，晚上照样不能刷。所以：

| 项 | 原来 | 现在 |
|---|---|---|
| 低谷窗口 | 23:30–08:00 | **18:00–08:00** |
| 每日自动叫醒 | 3 次 | **6 次** |
| 凌晨（00:00–08:00）上限 | 无 | **2 次**（给晚上留额度） |

改完实测：`能不能刷：可以（低谷时段）｜本次窗口剩余 25 分钟｜今日 3/6`。

## 3. 日记提醒有两套重复实现（顺手清掉）

`proactive.py` 的 morning/noon/evening/night routine 和 `diary-noon/midnight` 定时器
（`inject_diary.sh`）**发的是同样的提醒**。两套都开就是同一时段提醒两次。

而且我上一次同步 unit 时把这两个 timer 加进了安装清单——那会让新装机器也重复提醒。

清理：删掉 `diary-noon.timer`、`diary-midnight.timer`、`diary-inject@.service`、
`inject_diary.sh`，安装清单里也去掉。日记提醒统一由 routines 负责（可在 `routines.json` 里配）。

## 补丁数量：仍是 6 处

`MEM_HINT` 挂在已有的 `inbound.js` 补丁函数里（和主动接话、表情提醒同一处），
所以总数没涨。
