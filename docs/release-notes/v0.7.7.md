# v0.7.7 · 看图：被「叫醒」就看，图片接话单独 30%

v0.7.6 我把看图收成「只在她被 @ 且图在同一条消息里」，结果把用户真正想要的两条路一起堵死了：
群友发的图她完全看不见，被 @ 之后对话里接着发的图也不看。

用户要的是：

> 群里任何图都有 30% 概率被识别并回话（和主动接话同一个机制），
> 另外被 @ 之后那段对话里的图，也要识别。

## 两层配合

**1. 人设：改成「被叫醒就看」**

四种都算叫醒她：

```
① 私聊里主人发图
② 群里有人 @ 你，图就在这条消息里
③ 你正在跟某个人对话（他刚 @ 过你，这几分钟里他发的图也算跟你说话）
④ 群里没人 @ 你、但被抽中要主动接一句 —— 这时看到图就当作给你的素材
```

没叫醒的图一律不看：群友闲聊刷的图、历史旧图、自己发过的表情和图片。

**2. 插件：图片用单独的概率（第 6 处本地补丁）**

```yaml
imageEngageRate: 0.3        # 图片：三成会被「接住」→ 看一眼 → 接话
casualEngageRate: 0.2       # 文字：两成（保持原样）
casualEngageMaxPerHour: 3   # 两者共用这个小时上限
```

实现上只改了概率取值那一行：判断消息里有没有 `image`/`mface` 段，有就用
`imageEngageRate`，没有用 `casualEngageRate`。配额、冷却、时间格的逻辑一个字没动。

**安全设计**：`imageEngageRate` 读不到时回落 `casualEngageRate`。
所以即使 schema 没生效、配置没透传，行为跟改动前完全一致，不会突然变成 0 次。

## 顺带补的一个隐病

`casualEngageRate` / `casualEngageCooldownMs` / `casualEngageMaxPerHour`
这三个键一直只存在于**线上配置**里，`stack/cordis.patch.yml.tpl` 里没有——
也就是说**重新装一遍这些值就全丢了**。已补进模板。

这类问题的共性是：**线上手工改过的东西，没回到仓库就是一次性的**。
今晚已经踩过两次（qqguard.py、这条配置）。

## 没验的，以及一个必须说清的落差

**群聊里真实的 30% 行为没验**——注入通道进不了群，而验证“三成概率”需要真实群消息。

更重要的是这条：

> **图片和文字共用每小时 3 次的接话上限**（沿用原有配额）。
> 所以实际效果是「每小时最多 1~2 次图片接话」，**不是「每张图 30%」**。

如果你要的是「每张图独立掷 30%」，那得把图片配额从文字配额里拆出来、
并把 `casualEngageMaxPerHour` 调大。代价是调用量明显上升：假设一小时 10 张图，
按 30% 就是 3 次识别 = 10 秒左右 + 一两万 token。

这个取舍我没替你做，等你确认。
