**装完能用 QQ 聊天，但看不见任何图片。** 这一版只修这个，没有新功能。

## 症状

一切看起来都正常，只是她说"看不到图片"：`read_image`、表情分类、截图隐私判断
全部失效，而日志里没有明显报错。

## 三个原因叠在一起

### 1. 部署包里没有填看图端点的入口

`deploy.env.example` 里根本没有 `VISION_BASE` 这一项，而 `install.sh` 让它回落到
`$LLM_BASE_URL` —— 示例配置里那是 `https://api.deepseek.com`，**纯文本接口，
不接受图片输入**。

### 2. 占位符替换打错了路径

`install.sh` 只替换了 `profiles/web/local-memory/cordis.patch.yml`，但 npm 会把
`local-memory` 复制进 `node_modules`，**运行时读的是 `node_modules` 那一份**。
于是 `VISION_BASE: __VISION_BASE__` 原样进了 MCP 配置，看图请求被发到
`__VISION_BASE__/chat/completions`。

### 3. MCP 子进程不继承父环境

dsh 用配置里的 `env:` 段决定子进程环境。所以把 `VISION_BASE` 写进 `qwen.env`
（systemd 的 EnvironmentFile）**对 MCP 子进程无效**，必须写进 MCP 配置的 `env:` 段。

## 修法

- `deploy.env.example` 增加 `VISION_BASE` / `VISION_MODEL` / `VISION_API_KEY`，并写清
  "留空就回落到模型线路，如果那不支持看图就看不见图片"
- `install.sh`：装之前先检查端点，指向 `api.deepseek.com` 就明确警告
- `install.sh`：npm 安装后**同时**替换 `node_modules` 那份，并留守卫——占位符还在就
  `die`，而不是装完静默不工作
- `seer.py`：`api_key()` 在没有环境变量时从 `qwen.env` 读 `VISION_API_KEY`
- `verify.sh`：新增 **6.6 看图探测**，真发一张 1×1 的图，HTTP 非 200 就 FAIL

## 验证

容器里跑 `install.sh`（填了 `VISION_BASE`）：

```
node_modules/local-memory/cordis.patch.yml: VISION_BASE: https://vision.example.com/v1
占位符残留：0
```

线上实测：

```
真端点探测        HTTP 200
模拟 MCP 环境调用  "一只圆滚滚的蓝色卡通小鲸鱼正端着一碗冒着热气的白米饭。"
纯文本端点探测    401 → verify.sh 判 FAIL（这就是它该抓的）
```

## 升级现有部署

```bash
git pull
# 1) 在 deploy.env 里补上看图端点（如果你之前的接口本身支持图片，可留空）
VISION_BASE=https://your-multimodal-endpoint/v1
VISION_MODEL=支持图片的模型名

# 2) 重跑安装，或手动改配置
sudo bash install.sh

# 3) 验证（会真发一张图）
sudo bash verify.sh
```

如果你是在旧版本上手动修的，记得改**两个**地方：

```
profiles/web/local-memory/cordis.patch.yml
profiles/web/node_modules/local-memory/cordis.patch.yml   <- 运行时读这个
```

## 教训

**"配置写了"不等于"配置到了"。** 第一版我只往 `qwen.env` 里加了变量就以为修好了，
实际 MCP 子进程根本读不到 —— 这种失败不报错，只表现为"她看不见图"，和"模型不想
看图"几乎无法区分。所以这次加了一条会真发图片的探测，而不是检查配置文件里有没有
那行字。
