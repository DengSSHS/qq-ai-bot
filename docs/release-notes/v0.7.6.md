# v0.7.6 · 收回看图权限：群里别人刷的图，一律不看

v0.7.3 我为了让群友发的图也能看，把规则改成「只要这张图出现在你要回应的消息里，就先看」。
一小时后用户就报了问题：**群里任何一张图她都去识别**。

这是我改出来的回归。人设写得越宽松，账单越难看：一张图 3 秒、几千 token，
群里一晚上几十张图就是几十次调用。

## 修两层

### 第一层：人设收紧到「只在她被点名时看」

```
只有三种情况才看图：
  ① 私聊里主人发图
  ② 群里有人 @ 你，且图就在这条 @ 你的消息里
  ③ 主人明确说「看这张」

群里别人闲聊发的图，一律不看。哪怕图就飘在你眼前、哪怕你正要接一句话，
也不要为了「接得上」而去识别它。
```

### 第二层：代码兜底（`seer.py`）

人设只能提高概率，兜不了底。所以加硬上限：

```
每小时最多真正调用视觉模型 12 次
缓存命中的免费，不计额度
超限直接拒绝，并给她一句该说的话：
  「这一小时已经看过 12 张图，到上限了……跟发图的人说一声『这张我先存着，晚点再看』，
    别说自己不会看图。」
```

关键细节：
- **只对新图计数**。同一张图问两次，第二次走缓存，不扣额度（否则一张热门图能吃掉半小时额度）。
- **一小时的窗口是滑动的**（`now - t < 3600`），不是整点清零。
- 拒绝话术里明确「别说自己不会看图」——否则她会退化成「我看不到图」，那是另一个 bug。

## 自验

```
tests     132 passed（skipped=3，新增 5 个上限用例）
preflight 71 passed / 0 failed
线上      重启 dsh 后 seer 已加载（00:42:40），QQ 在线
```

上限用例覆盖了五件事：未超限正常调模型、到上限拒绝且**不调模型**、一小时前的旧调用
不占额度、缓存命中不扣额度、拒绝话术可执行。

## 教训

同一天内，我先把看图规则放宽（v0.7.3），再收紧（v0.7.6）。中间那版是我自己造成的回归。

根本原因不是判断错，而是**改这类规则时只想了「她要能看图」，没想「她会不会看太多」**。
凡是模型驱动、按次计费的动作（看图、生图、搜索、B 站），规则里都应该同时有
「什么时候该做」和「最多做多少」两句；只有前一句的规则，迟早会失控。
