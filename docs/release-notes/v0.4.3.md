工具版本。加了一条**补丁漂移检测**——上游插件改版导致本地补丁失效时，主动告警。

## 背景

`node_modules` 里现在有 5 处本地补丁，全在 `dsh-onebot-qq` 里：

```
prompt.js   长期记忆每轮注入
bridge.js   时间挪到后缀（前缀缓存）
inbound.js  主动接话概率门
index.js    配置 schema 与 gateConfig 透传
cq.js       未知表情兜底成 [表情]
```

锚点都是上游源码里的具体字符串。上游一改版就可能失配，而且**失配是静默的**：
不报错，只是某个功能悄悄不工作。（看图端点就这么坏过一整天。）

## patch_doctor.py

```
读本地已装版本 → 查 registry 最新 → 下载 tgz 解包
  → 在干净的新版上逐条打补丁 → node --check 自检
  → 有打不上的就告警
```

```bash
python3 patch_doctor.py           # 看报告
python3 patch_doctor.py --mail    # 必要时发邮件
python3 patch_doctor.py --ci      # 有漂移则退出码 2
```

两道防线：

| 位置 | 频率 | 动作 |
|---|---|---|
| GitHub Actions | 每周一 12:00 | 跑 `--ci`，失配标红 |
| systemd timer | 每周日 04:00 | 跑 `--mail`，失配发邮件 |

## 第一次运行就抓到真问题

```
本地已装：0.9.3      registry 最新：0.9.6

[DRIFT] prompt.js   跳过（结构已变）
[DRIFT] bridge.js   找不到目标行
[DRIFT] inbound.js  找不到插入点
[DRIFT] index.js    找不到插入点
[OK  ] cq.js        已打
```

核实过不是误报：0.9.6 的 `prompt.js` 从 96 行缩到 31 行（`readPersona()` 搬走），
`bridge.js` 的「当前时间」拼装也不在了。

**所以锁在 0.9.3 不是保守，是必要。** 升级到 0.9.6 的代价是重新锚定 4 处。

## 关于 fork 的判断线

补丁越多，升级成本越高。今天这笔账：

```
升级代价 = 重新锚定 4 处
不升级   = 拿不到上游修复
```

自用标准：

```
≤3 处   补丁脚本够用，升级时跟着改
4-5 处  必须上漂移检测（现在这里）
>5 处   该 fork 了
```

fork 的好处不是"改起来自由"，而是**升级变成一次 rebase，而不是五次猜锚点**；
坏处是 upstream 的安全修复要手动挑，合并冲突也要自己扛。

**更优的中间路线**：把通用性强的补丁提 PR 给上游，留私有的在本地。
比如 `cq.js` 那条——未知表情 id 不该兜底成 😀，因为那会让模型把「哭泣」
读成「开心」——这条对任何用这个插件的人都有价值，值得单独提。

不需要升级的部署可以跳过这一版，它只加了工具和文档。
