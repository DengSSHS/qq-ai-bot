# v0.7.30 · 清空重装验证：又抓到一个时序 bug

用同一台干净机做了一次完整的"清空 → 从零装"：
删掉 `/opt/dsh`、`/opt/node`、`/opt/qqbot`、所有 systemd unit、napcat 容器，
只保留 docker 与已缓存的镜像（模拟真实用户环境），然后用 v0.7.29 的代码重装。

## 抓到的 bug：服务没等就绪就验收

第一次重装结果：`13 passed, 5 failed`

```
[FAIL] 8643 onebot ws NOT listening
[FAIL] 8090 dsh web NOT listening
[FAIL] no 'bridge ready' in /var/log/dsh-onebot.log
[FAIL] OneBot not connected
[FAIL] checkall.py exit 1
```

但日志里明明写着：

```
[dsh-onebot] reverse WS server listening on ws://0.0.0.0:8643
dsh web: http://127.0.0.1:8090/?token=...
[dsh-onebot] bridge ready (0 resumed chat(s))
```

时间线对上了：install.sh `22:31:50` 启动服务 → `sleep 8` 就往下走 → verify 立刻跑，
而 dsh 真正把端口监听起来是 20 秒之后。**慢机器上必然误报。**

`systemctl is-active` 只说明"进程活着"，不代表"端口在听、bridge ready"。

### 修法

`install.sh`：固定 `sleep 8` → 轮询等 `8643` 和 `8090` 真正监听（最多 90 秒）：

```bash
for i in $(seq 1 45); do
  ss -lnt | grep -q ':8643 ' && ss -lnt | grep -q ':8090 ' && ready=1 && break
  sleep 2
done
```

`verify.sh`：也加最多 30 秒的端口等待——它可能被人单独运行（比如刚重启完），
同样会把"还没起好"误报成"没监听"。

### 修完重验

```
RESULT: 16 passed, 2 failed
[OK] dsh-onebot 运行中（8643 与 8090 已监听）
[OK] 插件版本豁免已写入
[OK] 定时任务已装：掉线看护 / 记忆蒸馏 / 收图结算 / 日报 / 漂移检测
```

剩下 2 项都是"没登录"的连带结果：

```
[FAIL] OneBot not connected    ← NapCat 在等扫码
[FAIL] checkall.py exit 1      ← 日记 0 个、FTS 索引未建、备份 0 份（全新机器的正常状态）
```

## 三个已知但没修的

1. **`preflight` 在部署目录必报两条**（`deploy.env` 必须存在 vs 不该被提交）——
   检查和部署用同一个目录，逻辑冲突。
2. **没跑到 `VERDICT: READY`**——最后一步要扫码，会踢掉生产机的鲸鲸。
3. **`checkall.py` 在新机器上必失败**（无日记/无索引/无备份），
   这个"失败"其实是正常状态，但会让人以为装坏了。应该按"是否首次安装"区分。
