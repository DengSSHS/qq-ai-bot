# v0.7.23 · 提醒里补「其余文件已更新」

> 如果发现他那里改了东西，那肯定是他那里要给他留着，就不给他更新，
> 然后给他提醒，然后其余地方还是给他更新的，毕竟很多 bug 是要修的

这个语义 v0.7.21/22 已经实现了——**逐文件判断**，不是"一有冲突就整体放弃"：

```
proactive.py  他改过 → 保留他的版本，新版放 proactive.py.new
qqguard.py    没人改 → 直接更新到新版（bugfix 照常落地）
notify.py     没人改 → 直接更新
```

但你这句"毕竟很多 bug 是要修的"让我发现提醒的一个缺口：

## 提醒原来只说"哪些没更新"

使用者收到通知后，没法判断 bug 修复到底有没有到账——他可能以为整个更新被跳过了。

现在正文多一段：

```
这些文件你（或使用者）改过，更新时保留了你的版本，没有覆盖：
  - proactive.py

其余 2 个文件已经正常更新到新版（包含本次的 bug 修复）：
  proactive.py, qqguard.py      ← 之类的清单

新版本已经放在同目录的「文件名.new」里，你可以：
  1. 什么都不做
  2. 用新版
  3. 先看差异
```

## 顺带修一个显示瑕疵

"无基线"那个分支（老机器第一次更新）原来把说明文字拼进了文件名，
导致后面的 diff 提示变成残废命令：

```
diff -u notify.py（无基线，已保守处理；确认后可 --adopt） notify.py（无基线…）.new
```

改成单独一行说明。

## 自验（三文件场景，逐文件判断）

```
proactive.py  被改  → 保留 + .new，没被覆盖
qqguard.py    没改  → 拿到 bugfix
提醒正文             → 同时列出「未覆盖」与「其余已更新」两类
通知失败             → 不写「已提醒」状态，下次重试
```

## 一句话总结这套机制

更新不是"要么全更要么全停"，而是**每个文件单独判断**：

- 你动过的 → 一个字不改，放个 `.new` 在旁边，发消息告诉你
- 你没动过的 → 照常更新，bug 修复不会因为你改了一个文件就全部延误
