这一版两个功能，都是被一次真实事故逼出来的：**QQ 掉了 12 小时，没人知道。**

## 事故

```
07:25:15  [KickedOffLine] 你的账号当前登录已失效，请重新登录
07:25:24  没有 -q 指令指定快速登录，将使用二维码登录方式
   ↓
19:18     有人上去查，中间 12 小时一条消息都没回
```

排除过：容器没崩（Up 16 小时、RestartCount=0、ExitCode=0）、没有 OOM（内核无记录，
内存 950M/1.9G + 1.9G swap）、网络正常。**是 QQ 云端踢的**，这类踢线服务端不会
告诉你原因，最常见是同一账号在别处登录。

## 关键发现：为什么每次都得人工扫码

`/app/entrypoint.sh` 里：

```bash
if [ -n "${ACCOUNT}" ]; then
  gosu napcat /opt/QQ/qq --no-sandbox -q $ACCOUNT   # 带 -q → 可快速登录
else
  gosu napcat /opt/QQ/qq --no-sandbox                # 不带 → 只能扫码
fi
```

`compose.yaml` 里 `ACCOUNT` 是配好的，所以**容器重启会带 `-q`**，能用保存的 token
自动登录。但被踢之后 NapCat 只做**内部重启 worker**，不走 entrypoint，`-q` 就丢了
→ 只能扫码等人。

所以修复方向不是"防掉线"（那是服务端决定的），而是**掉线后重启容器**。

## 新增：qqguard.py 掉线看护

每 2 分钟检查一次 OneBot 连接：

| 情况 | 动作 |
|---|---|
| 看到**新的** `KickedOffLine` | `docker restart napcat`，借 `-q` 重试快速登录 |
| token 还有效 | 自动恢复，不打扰任何人 |
| token 已失效 | 生成二维码，**停下等人工**，不再反复重启 |
| 一小时内 | 最多 3 次，避免和风控硬碰 |

「停下等人工」这条很关键：如果每 2 分钟重启一次，会把你正在扫的二维码刷掉，
永远扫不上。所以它只对"检测到之后的新事件"动手，扫码期间保持安静。

恢复后她会主动说一句：

> 主人，我刚才掉线了差不多 N 分钟，期间的消息可能没回。现在已经连回来了。

## 新增：邮件告警 + 日报

QQ 掉线时出站消息也发不出去，**用 QQ 通知自己是死路**。邮箱可以。

掉线告警邮件里含：断线时长、重启尝试次数、二维码解码链接（手机点开直接跳 QQ
授权）、以及二维码图片附件。

23:55 的日报也发一封邮件：用量 / 排障 / 预算 / 当天掉线事件。

> 日报除了看账，还兼"心跳"：**连着两天收不到日报，就说明机器或服务出问题了。**

## 配置（可选）

`deploy.env` 里填一项就开：

```bash
MAIL_PASS=xxxxx        # QQ 邮箱的「授权码」，不是 QQ 密码
```

发件人默认 `BOT_QQ@qq.com`，收件人默认 `OWNER_QQ@qq.com` —— 从已有配置自动推导。
不填就没有邮件功能，其它一切照常。

授权码获取：QQ 邮箱网页版 → 设置 → 账号 → POP3/IMAP/SMTP 服务 → 开启 → 生成。
**只显示一次。**

## 踩的坑

**授权码不是 QQ 密码，但报错不会告诉你这点。** 填错密码得到的是
`Connection unexpectedly closed`——完全不提认证，看起来像网络问题。

实测用同一把钥匙试两个邮箱，只有对应的那个能登录成功。所以 SMTP 配不通时，
先怀疑「钥匙和账号不配对」，别先排查网络。
