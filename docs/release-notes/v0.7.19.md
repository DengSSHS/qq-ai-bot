# v0.7.19 · 自动更新：每天凌晨 4 点自己检查

> 这个更新我更希望做成这种自动更新，每天的凌晨4点，然后扫描一下仓库有没有更新
> 如果有更新的话，就自动更新一下，然后这个自动更新应该也要给他一个关的渠道

## 新增 `auto-update.timer`：每天 04:00（±10 分钟抖动）

```
04:00  auto-update.timer → auto-update.service → /opt/dsh/auto_update.sh
         ├─ 查开关（关了就退出，三种关闭方式都认）
         ├─ git fetch，比较 HEAD..origin/main
         ├─ 没更新 → 记一行日志，结束
         ├─ 有更新 → 记回滚点 → git pull → bash update.sh
         ├─ 自检：服务起来了吗 / QQ 在线吗
         └─ 失败 → git reset --hard 回滚 → 再跑 update.sh → 通知主人
```

`update.sh` 本身"只增不改"，所以自动更新不会动你的配置值和改过的 prompt。

## 关闭渠道（三种，都实测过）

```bash
python3 /opt/dsh/switches.py off auto_update    # 推荐
systemctl disable --now auto-update.timer
touch /opt/dsh/memory/auto-update.disabled      # 兜底
```

实测：

```
switches.py off auto_update → auto_update 关
bash auto_update.sh         → 跳过：switches.py 里 auto_update = 关
switches.py on  auto_update → 开，定时器 enabled
```

`switches.py` 的清单里多了一项「每日自动更新」，和其它开关一起看/关。

## 顺带补：11 个 systemd unit 之前根本不在仓库里

查自动更新要装什么的时候发现的：仓库 `stack/systemd/` 只有 3 个 unit，
而作者机器上有 **11 个 timer**。也就是说别人装完，这些功能**根本不会跑**：

| 缺的 unit | 不装的后果 |
|---|---|
| `qqguard.timer` | 掉线没人管、也没告警 |
| `memory-distill.timer` | 长期记忆永远不提炼 |
| `sticker-settle.timer` | 收图结算不跑 |
| `usage-report.timer` | 没有日报 |
| `patch-doctor.timer` | 补丁漂移不自知 |
| `diary-noon/midnight.timer` | 日记提醒不发 |
| `bili-window.timer` / `tulpa-guard.timer` | B 站时间窗、Tulpa 看护 |

全部从线上同步进仓库，`install.sh` 里逐个 `enable --now`。
同时补上两个被 unit 引用但仓库里没有的脚本：`tulpa_guard.py`、`usage_daily.sh`
（preflight 第一个就抓到了 `usage-report.service needs usage_daily.sh`）。

## 自验

```
preflight 73 passed / 0 failed（比之前多 2 项：新增的文件也纳入检查了）
bash -n install.sh / auto_update.sh / usage_daily.sh  通过
线上：auto-update.timer 已装，NEXT 04:05:19
开关：off → 脚本跳过；on → 定时器 enabled
```

## 没验的

- **没有真的跑过一次“发现更新 → 升级 → 自检”的闭环**。服务器上那份部署不是 git 仓库（tarball 装的），
  脚本会正确地打印「找不到 git 仓库…跳过」。要完整验证，得有一台 `git clone` 部署的机器。
- 回滚路径（`git reset --hard` + 重跑 update.sh）只在代码层面写了，没有制造一次真实失败去跑它。

这两条都记在这，别当成"已验证"。
