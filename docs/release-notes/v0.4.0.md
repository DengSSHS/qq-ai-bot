这一版让她**会主动说话**——群里有 20% 的机会接一句，私聊里隔久了会自己找你。

顺带修掉一个静默失败 229 次的服务。

## 群聊：每条消息 20% 被她"接住"

原本未 @ 她的群消息被直接丢弃。现在多一道概率门：

```
未 @ 她 + 不在激活窗口
  → 掷 20% 命中 → 当作她想接一句，继续走完管线
  → 80% 未中  → 照旧丢弃
```

关键在于**它不进入激活池**：

- 接住的只有当前这一条，说完就结束
- 那个群友下次说话仍然需要 @ 她
- 她不是掺进对话里，而是**插一句就走**

所以不会出现"她突然开始跟一群人聊起来"。想继续聊，还是得 @。

另外两个约束：同群冷却 60 秒（连着刷三条不会三条都被接），以及这一轮会带上标记：

```
[主动插话] 这条没人 @ 你，是你自己看到想接一句。先看上面最近的群聊内容
（不够就调 qq_group_history 拉最近 10 条），再简短接一句就好，别追问、
别展开话题、别把话头接成长对话。
```

配置：

```yaml
casualEngageRate: 0.2          # 0 = 关闭
casualEngageCooldownMs: 60000
```

## 私聊：概率随时间累积

```
概率 = 每小时 +20% × (1 + 超出空闲门槛的小时数)，封顶 80%
默认：空闲 ≥60 分钟才考虑、窗口 08:30–23:30、静默时段不打扰
```

**是累积，不是每 10 分钟重投骰子**：同一小时内用小时桶哈希掷一次，
所以「闲置 1 小时 20%、2 小时 40%、3 小时 60%」是真的在涨。

## 修掉：一个静默失败 229 次的服务

`proactive.py` 里 `OWNER = __OWNER_QQ__` 从来没被替换过，于是
`proactive.service` 每 10 分钟 `NameError` 一次，**连续失败 229 次**。

后果不是"少一个提醒"：日记提醒（morning/noon/evening/night）从 10-22 之后
**全部没触发**，所以那两天她一条日记都没写 —— 之前看着像是"她不想写"。

`install.sh` 本来有统一替换（遍历 `$DSH_HOME/*.py`），是这台机器更早的安装
没跑那段。教训：**`list-timers` 显示 active 不代表跑得通**，装完要
`systemctl status` 看一眼。

## 踩的坑：配置键被白名单吞掉

插件把配置传给 pipeline 时要过 `gateConfig` 白名单（只挑固定几个键）。
加 zod schema 还不够——不在那个对象里的键，pipeline 读到的永远是 `undefined`。

表现：概率门静默失效（`rate=undefined`），行为完整退回原样，零报错。
排查方式是加一行探针把 `rate` 打出来，才看见是 `undefined` 而不是 `0.2`。

## 调参建议

20% 在活跃群偏高：一天 100 条群消息 → 约 20 次接话。嫌吵就调
`casualEngageRate: 0.1`，或把冷却改成 3 分钟。
