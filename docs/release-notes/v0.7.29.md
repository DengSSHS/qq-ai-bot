# v0.7.29 · 重装/更新不再冲掉别人的设定

> 这个在更新的时候，不要把别人的那个设置的个性化的东西给挤掉了，
> 比如说别人自己设定的什么作息呀，各种设定，以及别人自行设定的规则

上一版我做了 `update.sh` 的三方比对，但**漏了一条更常用的路径**：
`install.sh` 自己就在覆盖——

```bash
cp -f "$STACK"/*.py "$DSH_HOME"/                    # 无条件覆盖脚本
sed ... "$STACK/cordis.patch.yml.tpl" > cordis.patch.yml   # 整份重写配置
```

而 `deploy.sh` 失败后文档就是让人"重跑"，正好踩这个坑。

## 改了两处

### 第 6 步：脚本不再无条件覆盖

```bash
# 只拷"目标不存在"的文件；已存在的走三方比对
for f in stack/*.py stack/*.sh stack/*.json; do
    [ -e "$DSH_HOME/$(basename $f)" ] || cp -f "$f" "$DSH_HOME/"
done
python3 stack/sync_scripts.py     # 三方比对：没人动过→更新；动过→保留+.new
```

### 第 7.2 步：配置改成合并

```bash
if [ -f "$CFG" ]; then
  # 只补新版本新增的键，用户调过的值一个字不改
  python3 - "$CFG" "$TMPCFG" <<'MERGEPY' ... MERGEPY
else
  cp -f "$TMPCFG" "$CFG"        # 首次安装才整份写入
fi
```

```
  自定义行数：重装前 1，重装后 1                    ← 保住
```

## 顺带修的一个路径 bug

`install.sh` 调 `sync_scripts.py` 时报"找不到仓库目录"——因为脚本只认
`/opt/qq-ai-bot`、`/opt/dsh/repo` 这些固定路径，而实际部署常在 `~/qq-ai-bot`。
改成用 `REPO_DIR` 显式传仓库位置。

## 现在的保护矩阵

| 会被覆盖的东西 | 保护方式 |
|---|---|
| `/opt/dsh/*.py` `*.sh` | 三方比对（基线哈希），改过就保留 + `.new` |
| `cordis.patch.yml`（作息、概率、开关全在这） | 只补缺失键，旧值不动 |
| `routines.json`（各时段的提醒与 prompt） | 只添加新 routine，不覆盖已有 |
| `persona.md`（人设） | 存在就保持不动 |
| `/opt/dsh/*.conf.json`（B站窗口、预算等） | 不在同步范围内 |
| `node_modules` 插件代码 | **不保护**——用 `apply_local_patches.py` 的补丁方式改 |
