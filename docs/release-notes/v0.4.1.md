给 v0.4.0 的主动接话加一个**上限**。

## 问题

v0.4.0 的 20% 是**逐条**掷的：

```
一天 100 条群消息 → 约 20 次接话
而且很可能集中在前半小时就把话说完
```

在活跃群里这会显得话多，而且分布不均。

## 改成配额 + 均匀分布

```
把一小时切成 casualEngageMaxPerHour 个时间格（默认 3 格，每格 20 分钟）
每格最多接一次
```

**配额是天花板，20% 决定这一格要不要用。** 所以：

| 场景 | 行为 |
|---|---|
| 很安静的群（10 条/小时） | 约 2 次机会，多数时候不接 |
| 很活跃的群（100 条/小时） | 每 20 分钟最多 1 次，全天上限锁死 |
| 连着刷 3 条 | 同一格里只接一次 |

实测：同一个格内连发 3 条群消息 → **只接 1 次**，trace 里显示
「主动接话（第 1/3 格）」。

## 配置

```yaml
casualEngageRate: 0.2          # 每格被使用的概率
casualEngageCooldownMs: 60000  # 两次接话的最小间隔
casualEngageMaxPerHour: 3      # 每小时上限（切成这么多格）
```

`casualEngageMaxPerHour: 3` 是最直接的旋钮，想更安静就调到 2 或 1。

## 其它

- `apply_local_patches.py` 同步更新（含新增字段的初始化），新装也是配额版
- 私聊的累积概率不受影响，仍是「每小时 +20%，封顶 80%」

## 升级

```bash
git pull
sudo bash install.sh
python3 /opt/dsh/apply_local_patches.py --check
```

只想改参数不必升级，直接编辑
`/opt/dsh/profiles/web/cordis.patch.yml` 里的三个 `casualEngage*` 键，
然后 `systemctl restart dsh-onebot`。
