## 第 2 条：`rank()` 给所有候选 hits+1 —— 是副作用，不是设计

旧实现：

```python
def rank(items):
    ...
    for head, body in items:
        ...
        scored.append((s, head, body))
        e["hits"] = int(e.get("hits", 0)) + 1   # ← 所有候选都加
        store[head] = e
    _save(store)                                 # ← 每次都全量写盘
```

两个问题：

1. **语义错了**：常被检索、但从未被真正注入上下文的记忆也在被强化。
   复述强化应该奖励"真的被想起来并用了"，不是"进过候选池"。
2. **I/O 浪费**：每次检索都全量重写 `index.json`。

改成职责分开：

```python
def rank(items):        # 纯函数：只排序，不写盘
def reinforce(heads):   # 只对真正注入的条目 hits+1，落一次盘
```

调用方按各自语义接线（`memory_server.py` 两处）：

| 调用点 | 语义 | 强化谁 |
|---|---|---|
| `picked = rank(picked)` | 全部会返回、全部会用上 | 全部 |
| `rank(hits)[:n]` | 只有前 n 条会注入 | 只前 n 条 |

### 实测（线上真实日记库）

```
rank() × 3        → index.json 未被改写（纯函数）
reinforce([第一条]) → 第一条 1→2，其余 4 条仍为 0
diary_search("累") → 正常返回 1 条，hits 只加到那一条（1→3，其余 0）
```

### 迁移：不清零

反馈建议二选一（不管让它衰减 / 清零重来），倾向 ①。同意，而且实测发现
这台机器 `max hits = 1`、平均 0.2——膨胀还没真正发生，更没理由清掉真实痕迹。
