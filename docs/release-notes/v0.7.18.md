# v0.7.18 · 更新通道：别人不再需要回来问你

> 自动更新对了，这个东西没有啊，导致别人更新的时候都要重新让我去说明这是一个大问题

确实是个大问题，而且比“麻烦”更严重：**没有更新通道时，重跑 `install.sh` 会把手调过的配置全部覆盖掉。**

## 两个真实的洞

**1. 没有 `update.sh`**

`install.sh` 第 7 节是这么写配置的：

```bash
sed -e "s|__LLM_BASE_URL__|...|" "$STACK/cordis.patch.yml.tpl" > "$DSH_HOME/profiles/web/cordis.patch.yml"
```

`>` 是**整体覆盖**。所以“升级”只能重跑 install，而重跑就等于把你改过的
`casualEngageRate`、`stickerNudgeRate`、`newMessagePolicy` 这些全部打回模板默认。

**2. `routines.json` 从来没进安装流程**

全仓库只有 `stack/config/routines.json.tpl` 这一个模板文件，
而 `install.sh` 里**没有任何一行**引用它。

后果：别人装完之后 `proactive.py` 读到的是空列表 ——
**主动私聊、日记提醒、空间说说，全都不存在**，安安静静什么都不做。
（这也解释了为什么之前要“回来问作者”：不只是不知道怎么更新，是压根没装上。）

## `update.sh` 做了什么

```bash
git pull && bash update.sh
```

| 步骤 | 行为 |
|---|---|
| 1 代码 | 可选 `--pull`，打印当前版本 |
| 2 配置补键 | **只补缺失的键**，已有值一字不动 |
| 3 日程补项 | 只添加新 routine（按 id 比对），不覆盖已有 prompt |
| 4 插件 | 重装 fork 快照 + 重打本地补丁 |
| 5 重启 | `systemctl restart dsh-onebot` + 确认起来 |
| 6 自检 | 跑 preflight，打印 qqguard 状态 |

幂等；`--dry-run` 只看不改。

### 配置合并怎么做到“只增不改”

按缩进级别找插入位置，逐键判断是否已存在：

```python
for line in 模板:
    k, indent = key_of(line)
    if k in 已有键:      → 跳过（绝不覆盖）
    else:                → 插到配置里"同缩进的最后一个键"之后
```

实测（拿服务器真实配置，删掉两个键模拟旧版本）：

```
合并前：缺 stickerNudgeRate, injectDryRun
        casualEngageRate: 0.2        ← 自定义值
        newMessagePolicy: steer      ← 自定义值
合并后：新增 stickerNudgeRate, injectDryRun
        casualEngageRate: 0.2        ← 一字未改
        newMessagePolicy: steer      ← 一字未改
```

## 顺带修掉的那个更大的洞

`install.sh` 新增一段：**`routines.json` 不存在时才从模板创建**。

```
[OK] routines.json 已装（主动私聊/日记/空间）
```

已存在则保持不动（更新交给 `update.sh` 补新项，不会覆盖你改过的 prompt）。

## 没验的

`update.sh` 的完整流程没有在干净机器上跑过（第 4-6 步需要真实服务器）。
配置合并和日程合并两段是单独验证过的；重启与自检两步与 `deploy.sh` 用的是同一批命令。
