# 本地补丁：5 处，和上游漂移的真实代价

`node_modules/dsh-onebot-qq` 里有 5 处本地补丁，由 `apply_local_patches.py` 维护，
`patch_doctor.py` 每周检查上游新版还能不能打上。

这份文档只记一件事：**漂移发生时，代价有多大，怎么判断该不该跟。**

## 当前状态（2026-10-25）

| | |
|---|---|
| 本地运行 | **0.9.3**（已打 5 处补丁，运行正常） |
| 上游最新 | 0.9.6 |
| 漂移检查 | 4 处对不上、1 处仍可打（`cq.js`） |
| 结论 | **不升级**。等有实际需要（上游修了影响我们的 bug）再一次性移植 |

## 每处补丁为什么存在

| 文件 | 补丁 | 不打的后果 |
|---|---|---|
| `prompt.js` | 长期记忆注入（每轮把 AGENTS.md 内容拼进系统提示） | 她失忆：日记/笔记照写，但不会读回来 |
| `bridge.js` | 时间戳挪到消息尾部 | 前缀缓存失效，每轮多花几千 token |
| `inbound.js` | 主动接话概率门 + 表情提醒 | 群里她不主动接话；表情提醒也没了 |
| `index.js` | 配置 schema + **白名单透传** | 新配置项写了等于没写（静默失效，无报错） |
| `cq.js` | 未知表情兜底成 `[表情]` | 未识别的表情会渲染成乱码/空 |

## 0.9.6 改了什么（实测对比）

| 文件 | 0.9.3 | 0.9.6 | 说明 |
|---|---|---|---|
| `prompt.js` | 134 行 | **31 行** | 只剩 `buildPlatformPrompt`，记忆装配被搬走 → 锚点没了 |
| `inbound.js` | 714 行 | 555 行 | 结构性重构，旧 `@` 门槛还在但打包逻辑变了 |
| `bridge.js` | 1113 行 | 965 行 | 拆分到 `outbound.js`/`deferred.js`/`interim.js` 等 |
| `index.js` | 453 行 | 421 行 | `groupActivationMinutes` 那行的写法变了 → schema 锚点没了 |
| `cq.js` | 266 行 | 238 行 | 唯一还能打上的 |

## 一个更要紧的发现

0.9.6 的平台提示里写着：

> 用户发来的图片/语音/视频在消息文本里标注为 `[图片]/[语音]/[视频]` 占位（**本地路径不进入文本**）

而我们的看图功能全靠 `[图片:/opt/dsh/media/onebot/xxx.jpg]` 这个路径工作。
如果 0.9.6 真的不把路径交给模型，那么升级后**看图会整体失效**，
需要重新设计（比如改成图片直接走多模态，或者另外提供工具按 message_id 取图）。

所以这次升级不是“重新对齐 4 个锚点”那么简单，是一次**功能级迁移**。

## 升级时应该怎么做（备忘）

1. 在**旁路**解包新版，先只打 `cq.js`（最简单那处），跑 `node --check`
2. 逐处移植，每处都要能回答“锚点为什么变了、新代码等价物在哪”
3. **重点验看图**：新版的入站文本里到底还有没有本地路径
4. 全部就位后，用 `cp -a` 备份旧 `node_modules/dsh-onebot-qq`，再替换
5. 重启 dsh → 检查：她会不会回话、能不能看图、群里会不会主动接话、表情能不能发
6. 任一项不对 → 立刻回滚（备份目录改回来 + 重启）

## 为什么当初要打这么多补丁

不是因为爱改上游，而是这些能力上游没有：长期记忆注入、前缀缓存优化、
主动接话、表情提醒、配置白名单透传。

**5 处是个分水岭**：再往上加，每加一处就是一次未来的迁移成本。
所以以后新增能力，先问：能不能不改上游实现？能不能用 MCP 工具/配置解决？
只有“必须拦在消息管线上”的，才值得打补丁。
