# 怎么测她，而不打扰你

2026-10-26 加。起因：每次测试都往主人 QQ 发一堆没头没尾的话，她还一边回「不接这条」一边照发。

## 一句话

```bash
cd /opt/dsh && python3 qq_test_inject.py '在吗'
```

她照常跑完整回合（读人设、查记忆、调工具），但**出站全部被拦**，你 QQ 一条都收不到。
工具会把「她本来会发什么」打印出来。

## 为什么不能只用 `injectDryRun`

`injectDryRun` 是**全局**开关，而注入通道同时是「主动消息投递」的唯一通道：

| 开关 | 主动消息 | 测试消息 |
|---|---|---|
| `true` | 发不出去 | 安全 |
| `false`（当前） | 正常 | **会真的发到你 QQ** |

所以把决定权下沉到**每条事件**：注入行带 `"dry_run": true` 就只拦那一轮。

## 实现（`apply_local_patches.py` 第 6 个补丁）

1. **按条 dry-run + 时间窗**：带 `dry_run` 的注入消费时开一个 120 秒窗口，
   窗口内该会话的出站一律拦。为什么用时间窗而不是轮次关联——异步的最终回复
   跑在 ALS 上下文之外（`turn/end` 之后才发），拿不到 round，只能靠时间窗兜住。
2. **真实消息立刻关窗**：`noteDispatch` 收到非注入的 dispatch 就清掉窗口，
   免得你在测试期间说话也被吞。
3. **拦截写日志**：`[注入拦截] send_msg（dry_run 时间窗） :: 她本来说的话`。
   （原来只发 trace 事件，日志里啥也看不到，排障抓瞎。）
4. **`as_user`**：注入默认会被改标成「系统·内部提醒」，她会一致回「不接这条」，
   测出来的东西没参考价值。测试工具默认带 `"as_user": true` 按主人身份进管线；
   出站已拦，QQ 收不到，代价只是这条假消息会进她的上下文。

## 实测记录

```
01:4x  注入「用一句话告诉我现在几点了」→ 她本来会说「一点四十二，快睡吧。」   QQ 增量 0
01:5x  注入「在吗」                    → 她本来会说「在。」                 QQ 增量 0
```

## 注意

- 注入通道在插件文档里标注 **DEBUG-ONLY**。现在拿它当主动消息的投递通道是权宜之计，
  长期应改成「内容由模型生成 → 直接调 OneBot HTTP 接口发送」，那时链路才有真正的
  投递保证（现在重启会跳过未消费的行，见 CHANGELOG v0.7.39）。
- 测试会在她的上下文里留下「主人说过 X」，别拿它测敏感话题。
